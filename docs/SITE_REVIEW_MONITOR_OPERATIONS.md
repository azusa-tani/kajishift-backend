# KAJISHIFT サイト確認モニター運用メモ

最終更新: 2026-07-08  
確認者: `KAJISHIFT運用担当`

このドキュメントには、個人名、メールアドレス、電話番号、住所、問い合わせ本文、審査回答本文、問い合わせID、userId風の値、workerId、bookingId、予約ID、submissionId、APIキー、Secret、DB接続文字列、決済情報の実値を記録しない。

## 1. 目的

2026年7月7日にA案「本番決済なし限定公開」として公開したKAJISHIFTについて、Instagram経由で募集する **サイト確認モニター** の運用方針を整理する。

サイト確認モニターは、家事代行サービスの実働を伴う一般モニターではない。Webサイトの見やすさ、サービス内容の分かりやすさ、不安点、問い合わせ・事前登録・β利用希望への導線を確認し、正式予約や本番決済が開始済みに見えないかを確認するための協力者として扱う。

## 2. 現在の公開状態

- 2026年7月7日にA案「本番決済なし限定公開」として公開済み。
- 2026年7月8日時点でInstagramアカウント作成済み。
- 現在は正式サービス開始ではなく、問い合わせ、事前登録、β利用希望、サービス内容閲覧を中心とした限定公開。
- 現時点では家事代行の実働対応は開始しない。
- 問い合わせ、事前登録、β利用希望、サイト確認モニター応募は、正式予約ではなく運営からの個別案内対象として扱う。

## 3. サイト確認モニターの定義

サイト確認モニターは、KAJISHIFTのWebサイトを閲覧し、利用者目線で分かりにくい点や不安に感じる点をフィードバックする協力者。

以下の性質を明確にする。

- 家事代行の実働は伴わない。
- 正式予約、契約成立、本番決済、カード登録、課金は伴わない。
- サイト閲覧とフィードバック収集が目的。
- 申し込み前の不安、導線の分かりやすさ、A案の誤認リスクを確認する。
- 必要以上の個人情報、詳細住所、決済情報の入力は依頼しない。

## 4. A案で受付可能なもの

A案で受付可能な範囲は以下に限定する。

- 問い合わせ
- 事前登録
- β利用希望
- サービス内容の閲覧
- サイト確認モニターからのフィードバック

受け付けた内容は、正式予約や実働依頼として扱わず、運営確認後の個別案内対象として扱う。

## 5. A案で開始しないもの

A案では以下を開始しない。

- 家事代行の実働
- 正式予約
- 本番決済
- 本番カード登録
- 本番課金につながる導線
- worker受注・辞退・作業完了
- 管理画面の更新・削除・承認/却下などの更新系操作

Instagramや個別案内でも、上記が開始済みに見える表現は避ける。

## 6. Slack通知・管理画面の確認ルール

Slack通知や管理画面で問い合わせ、事前登録、β利用希望、サイト確認モニター応募を確認する場合は、読み取り限定で確認する。

押してはいけない操作:

- `対応する`
- `自分にアサイン`
- `対応開始`
- `削除`
- `承認`
- `却下`
- `合格`
- `不合格`
- 停止 / 有効化
- CSV / Excel出力
- 予約作成、予約確定、決済、カード登録、承諾、辞退、作業完了につながる操作

docsへ記録してよい情報:

- 確認日
- 確認者 `KAJISHIFT運用担当`
- 受付種別
- 件数などの集計値
- 読み取り限定で確認したこと
- 正式予約、本番決済、実働として扱っていないこと
- 次対応の抽象メモ

docsへ記録してはいけない情報:

- 個人名
- メールアドレス
- 電話番号
- 住所
- 問い合わせ本文
- 審査回答本文
- 問い合わせID、userId風の値、workerId、bookingId、予約ID、submissionId
- APIキー、Secret、DB接続文字列
- 決済情報の実値

## 11. サイト確認モニターに依頼する確認観点

サイト確認モニターには、以下の観点で確認を依頼する。

- トップページを見て、サービスの概要が分かるか。
- サービス内容、対象エリア、利用対象が分かりやすいか。
- 料金や利用の流れが分かりやすいか。
- 「問い合わせ」「事前登録」「β利用希望」の違いが分かるか。
- どこから問い合わせればよいか分かるか。
- 申し込み前に不安に感じる点があるか。
- 本番決済、正式予約、カード登録が開始済みに見える箇所がないか。
- 家事代行の実働モニター募集と誤解されないか。
- スマートフォンで見にくい箇所がないか。
- 表現が難しい、長い、分かりにくい箇所がないか。

## 12. フィードバック受付時の記録ルール

フィードバックを受け付けた場合、docsには実値を残さず、以下のように抽象化して記録する。

記録例:

- `2026-07-08 サイト確認モニター応募を確認。正式予約・本番決済・実働依頼としては扱わず、個別案内対象として整理。`
- `2026-07-08 サイト確認フィードバックを確認。導線に関する改善候補として別タスク化を検討。`

記録しない例:

- 氏名、メールアドレス、電話番号、住所
- 問い合わせ本文やフィードバック本文の原文
- URL内または画面上のID実値
- 決済情報、カード情報、Secret類

## 13. 禁止事項・注意事項

- サイト確認モニターを家事代行の実働モニターとして案内しない。
- 正式予約、本番決済、カード登録、課金が開始済みに見える表現を使わない。
- Instagramから予約作成、決済、カード登録、worker受注系のページへ直接誘導しない。
- Slack通知や管理画面確認時に、更新・削除・承認/却下などを押さない。
- フィードバック本文や個人情報をdocsに転記しない。
- スクリーンショットを保存する場合は、個人情報、ID風の値、Secret類、決済情報が写り込まないようにする。
- `Screenshots/` はGit管理対象にしない。
